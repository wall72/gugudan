# 코드 리뷰 및 개선 제안

## 리뷰 개요

- 리뷰 대상: CLI와 Flask 웹 인터페이스를 제공하는 구구단 앱 전체
- 리뷰 일자: 2026-06-04
- 검증 명령: `pytest`
- 전체 판단: 핵심 계산 로직, CLI, 웹 진입점, 하위 호환 API가 작게 분리되어 있어 유지보수하기 쉬운 구조입니다. 현재 자동 테스트도 핵심 동작과 웹 요청의 기본 흐름을 잘 검증합니다.

## 현재 구조 요약

```text
gugudan/
  engine.py   # 순수 계산 로직
  base.py     # 앱 추상 기반 클래스
  cli.py      # CLI 인터페이스
  web.py      # Flask 웹 인터페이스
  __init__.py # 하위 호환 함수/API 노출
main.py       # 실행 모드 선택 진입점
tests/        # pytest 기반 테스트
```

## 좋은 점

1. **도메인 로직과 UI가 분리되어 있음**
   - `GugudanEngine`은 입출력에 의존하지 않고 구구단 행 생성만 담당합니다.
   - CLI와 웹은 같은 엔진을 재사용하므로 인터페이스 추가가 비교적 쉽습니다.

2. **기존 API와 새 구조의 공존**
   - `gugudan.__init__`에서 `multiplication_table`, `print_multiplication_table`, `parse_input`을 유지해 하위 호환성을 제공합니다.

3. **테스트 범위가 핵심 경로를 포함함**
   - 구구단 생성, 음수/0 입력, 종료 토큰, 잘못된 입력, 웹 GET/POST 흐름이 테스트되어 있습니다.

4. **의존성이 작음**
   - 런타임 의존성은 Flask 중심이고, 개발 의존성은 pytest만 추가되어 프로젝트 규모에 적절합니다.

## 상세 리뷰

### 1. 입력 범위 정책을 명확히 해야 함

현재 앱은 `int()`로 변환 가능한 모든 정수를 허용합니다. 테스트도 0과 음수를 정상 입력으로 검증하고 있습니다. 반면 README의 설명은 “구구단(1~9)”처럼 읽힐 수 있어 제품 정책이 불명확합니다.

- 선택지 A: 학습용 곱셈표 앱으로 보고 모든 정수를 허용한다.
- 선택지 B: 일반적인 구구단 앱으로 보고 2~9 또는 1~9만 허용한다.

권장안은 정책을 먼저 정한 뒤, `GugudanEngine` 또는 별도 입력 검증 함수에 규칙을 모으는 것입니다. 이렇게 하면 CLI와 웹, 하위 호환 API가 같은 기준으로 동작합니다.

### 2. 입력 파싱 로직 중복

`GugudanCLI.parse_input()`과 패키지 레벨 `parse_input()`이 같은 종료 토큰 처리와 정수 변환 책임을 나누어 가지고 있습니다. 현재는 내용이 짧아 문제가 작지만, 향후 입력 범위 제한이나 메시지 정책이 들어오면 두 곳이 쉽게 어긋날 수 있습니다.

권장 개선 방향:

1. `gugudan.input` 또는 `gugudan.parser` 같은 작은 모듈을 만든다.
2. `parse_input(raw: str) -> int | None`을 한 곳에 둔다.
3. CLI와 하위 호환 API가 같은 함수를 호출하도록 바꾼다.

### 3. 웹 템플릿 분리

현재 `web.py`에 HTML/CSS가 문자열로 포함되어 있습니다. 앱이 작을 때는 단순하지만, UI가 조금만 커져도 Python 라우팅 코드와 프레젠테이션 코드가 섞여 읽기 어려워집니다.

권장 개선 방향:

```text
gugudan/
  templates/
    index.html
```

으로 템플릿을 분리하고 `render_template()`를 사용하면 Flask 관례에 맞고 유지보수성이 좋아집니다.

### 4. 라우트 핸들러의 예외 범위 축소

웹 POST 처리에서 `ValueError`를 잡는 구조는 현재 충분히 단순합니다. 다만 입력 변환, 도메인 검증, 테이블 생성이 늘어나면 어떤 단계의 오류인지 구분하기 어려워질 수 있습니다.

권장 개선 방향:

- 문자열 → 정수 변환 실패
- 범위 검증 실패
- 기타 예상하지 못한 오류

를 분리해 사용자에게 명확한 메시지와 적절한 HTTP 상태 코드를 반환합니다.

### 5. 테스트 보강

현재 테스트는 핵심 동작을 잘 검증하지만 다음 영역은 추가하면 좋습니다.

- `GugudanEngine.generate_range()`의 시작/끝 범위 검증
- CLI에서 잘못된 입력 후 재입력하는 흐름
- `KeyboardInterrupt`, `EOFError` 종료 처리
- `main.py --mode web --host ... --port ...` 인자 전달 검증
- 입력 범위 정책 확정 후 경계값 테스트

### 6. 타입 힌트 정교화

`main.py`의 앱 레지스트리는 `dict[str, type]`로 선언되어 있습니다. 현재 실행에는 문제가 없지만, 생성자 시그니처가 서로 다르거나 새 앱 타입이 추가될 때 정적 검사가 충분히 도움을 주기 어렵습니다.

권장 개선 방향:

- 공통 인터페이스를 반환하는 factory callable로 표현한다.
- 또는 `type[GugudanApp]`처럼 기반 클래스를 명시한다.

### 7. 빈 루트 모듈 정리 검토

루트에 빈 `gugudan.py`가 있습니다. 실제 패키지 디렉터리 `gugudan/`과 이름이 같아 신규 기여자에게 혼동을 줄 수 있습니다. 하위 호환 목적의 파일인지 확인한 뒤 README나 주석으로 의도를 남기거나, 필요 없다면 별도 작업에서 제거하는 것을 검토할 수 있습니다.

> 안전 규칙상 파일 삭제는 별도 확인 후 진행하는 것이 좋습니다.
